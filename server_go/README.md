# Go 棋牌游戏大厅全栈单体核心服务 (Game Hall Monolith)

高性能单体微内核架构，支持高并发棋牌房间实时匹配、分布式状态同步与事务级结算。

## 核心游戏规则与引擎支持

1. **斗地主 (Doudizhu)**
   - 规则：叫地主机制 (1/2/3分)、单张/对子/顺子/三带一/三带二/飞机带翅膀/连对/四带二/炸弹/王炸 (火箭)。
   - 倍数结算：炸弹翻倍、火箭翻倍、春天 (2倍)、反春 (2倍)。

2. **锄大地 (Big Two / 广东/香港规则)**
   - 规则：方块3首出、花色比较 (黑桃 > 红桃 > 梅花 > 方块)、2最大。
   - 牌型：单张、对子、三条、顺子、同花、葫芦、铁支 (四带一)、同花顺。
   - 惩罚机制：未出牌/一条龙包赔 (4倍)、三炒 (3倍)、双炒 (2倍)。

3. **跑得快 (Pao De Kuai / 湖南/江浙规则)**
   - 规则：16张扑克牌、黑桃3首出、有牌必打、顶大规则 (报单顶大牌)。
   - 牌型：单张、对子、顺子、连对、炸弹 (现结)、三带二。
   - 结算：输家按手牌剩余张数结算，关门包赔双倍。

4. **十三水 (Chinese Poker / 十三张)**
   - 规则：每人发13张，分为头道 (3张)、中道 (5张)、尾道 (5张)。
   - 倒水判定：尾道必须大于等于中道，中道必须大于等于头道，违者判倒水全赔。
   - 特殊牌型：一条龙 (108水)、清一条龙 (1080水)、十二皇族、三同花顺、三分天下、六对半等。
   - 枪击与全垒打：打枪翻倍 (+100%)，全垒打所有对手翻4倍 (+300%)。

5. **四川麻将 (血战到底 / 国标规则)**
   - 规则：108张筒条万、定缺门 (必须打光缺门才能胡牌)、碰/杠/暗杠/点杠/补杠。
   - 胡牌算法：通用 3N+2 递归判定 + 七对子判定。
   - 血战到底机制：一家胡牌后牌局不结束，其余三家继续摸打，直到三家胡牌或摸完荒牌。
   - 番数计算：平胡、清一色 (4番)、七对 (4番)、金钩钓、杠上花、海底捞月。

## 系统高并发架构设计

```
 [ WebSocket / HTTP 客户端网关 ]
               │
               ▼
 [ gRPC 内部跨服务高速网格 (Proto3) ]
  ├── MatchmakingService (无锁 Goroutine 队列池, 目标 <2ms 配对)
  ├── GameRoomService (状态机、出牌合法性核验、倒计时事件)
  └── SettlementService (事务锁扣款、抽水 5%、对账流水审计)
               │
               ▼
 [ Redis 高性能内存状态集群 ]
  ├── Lua 脚本原子性房间锁 (NX PX 分布式互斥)
  ├── Lua 脚本原子状态更新与出牌轮转 (单次网络 RTT)
  ├── Pub/Sub 广播房间状态变更至网关
  └── ZSET 排行榜与匹配排队权重
```

### 1. gRPC 跨游戏服务总线 (`proto/game.proto`)
- 内部低开销序列化，传输延迟低于 0.2ms。
- 无论单体部署还是横向拆分集群，无需修改接口协议。

### 2. Redis 内存状态同步
- 状态存储于 `room:{id}:state` Hash，TTL 自动续期。
- 关键操作使用内置 Lua 脚本保证原子性，绝无脏读或并发超卖。

### 3. 实时匹配队列 (`pkg/matchmaker`)
- 基于 Go 原生 Channel 与 Sync 锁池实现轻量排队。
- 支持动态阶梯底分 (新手/进阶/高手/宗师)。
- 设有 2.0s 超时兜底机制，自动补全智能 AI 陪练，杜绝冷启动等待。

## 快速编译与运行

```bash
# 1. 生成 gRPC 代码 (可选)
make proto

# 2. 编译可执行文件
make build

# 3. 运行本地服务
./bin/gamehall-monolith
```

服务启动后监听：
- **HTTP/Gateway**: `http://localhost:8080` (支持 `/healthz` 与 `/metrics`)
- **gRPC Mesh**: `localhost:50051`
